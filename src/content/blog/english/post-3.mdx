Database performance problems can originate from query design, indexing, configuration, resource constraints, storage latency or application behavior. Effective optimization begins with evidence rather than assumptions.

## Identify the actual bottleneck

Establish when the problem occurs and which workloads are affected. Review database metrics alongside operating system and storage indicators.

Useful signals include query latency, throughput, CPU utilization, memory pressure, disk I/O, lock waits, connection usage and replication lag.

## Analyze expensive queries

Use the database platform's execution plans and query statistics to identify expensive operations.

Look for:

- Full scans on large tables
- Inefficient joins
- Missing or unsuitable indexes
- Large sorts and aggregations
- Unnecessary data retrieval
- Poorly selective filters

An index should be introduced based on workload evidence. Too many indexes can increase storage requirements and write overhead.

## Review database configuration

Check memory settings, connection limits, parallel execution, checkpoint behavior and storage configuration against the actual workload and available resources.

Configuration changes should be measured and tested rather than applied as generic tuning recipes.

## Maintain useful statistics

Query planners depend on statistics to estimate row counts and choose execution plans. Keep statistics current, especially after bulk loads, large data changes and migrations.

## Measure the outcome

Capture a baseline before changing the system. Compare execution time, resource consumption and workload throughput after each meaningful change.

## Conclusion

Performance optimization is an iterative process: measure, identify, change and validate. A disciplined approach helps teams improve database efficiency while reducing the risk of unnecessary configuration changes.
